# diff-list

输入明确仓库与 Git 修订，可多项目。仓库可传 HTTP(S) 地址或本地 Git 工作区路径；本地路径会被克隆到新的隔离无检出目录，避免先拒绝路径再切换地址。基于提交对象分析，不纳入未提交的工作区改动；来源仓库只读。每次使用当前版本重新采集、分析并生成报告，不复用或迁移历史分析产物。每次分析创建新的隔离仓库，内部复用固定快照。脚本不构建目标项目、不执行 SQL、不提交或推送；分析目录保留供复核。

## 标准流程

1. 接到差异分析任务后，先固定用户指定的仓库与修订并执行 `scripts/analyze.py`，取得 analysis.json/context.jsonl；默认范围流程不先创建 Markdown 报告。合并提交明确 parent，多项目使用 manifest。自定义注解、配置作用域和仓库特有的关键未解析调用接收者/方法，通过显式 `--rules` 适配，RHF 样例为 rules/rhf.json。
2. 读取 [10 分钟范围审查模板](references/fast10-review-template.md)、[分析契约](references/analysis-contract.md) 和 [检查清单](references/analysis-checklist.md)，使用 `scripts/review_workbench.py --fast10`，默认按退款、支付/流水号、通知回调等业务职责合并为不超过 8 个主流程候选。退款相关方法先看 `method_timeline` 的最终实现，再按行为变化摘要核对确实改变外部可见行为的中间提交；不因每次提交都重新归并整段历史。配置项先使用 `configurations` 中的消费者索引一次列出读取位置、入口、条件与使用点，再逐入口核实差异，不重复全仓搜索。分支和调用关系只作支持证据，不单独计为测试场景；只有会改变关键状态、单号、金额、渠道请求、通知或响应的路径才拆分。组内保留关联义务/事实/证据 ID，成员适用条件不同不得共用结论。无法归入主流程的关系列入范围外统计，不判定为无影响，也不因此阻止所选范围交付。只保留可能影响数据库、渠道、QCM、通知、退款状态或最终响应的未解析调用；不因参数文本关键词单独触发。调用关系最多向上、向下扩展 2 层，每个快照最多选取 100 个方法。受影响 Java 文件无法索引、变更方法超限或关键变更证据缺失时作为阻塞错误报告。默认目标是 10 分钟内完成范围选择、证据复核、报告和用例；复核只按范围视图中的义务和证据 ID 读取源码，不整份载入 analysis/context；不得为清空全量工作台队列而追加扫描。忽略新增单元测试方法；离散提交读取合成结果树，合成失败不得扩大范围。
3. 登记语义不同且确实影响关键结果的测试场景，覆盖所选正常业务流程及少量高风险例外。维护唯一滚动清单：发现候选时立即按规范身份查重并关联来源/义务；相容场景当场合并，不在末尾整批回头归并。每条用例都要写清配置/数据前提、可直接执行的步骤和可观察的预期结果；不能只列候选标题。已核实的正常流程可归为需求验收，不声称用户确认了未提供的需求；实例值放数据组，语义等价须有源码依据。
4. 每次调用必须生成并交付一份范围内完成的 Markdown 报告和一份独立测试用例 Excel。报告沿用固定章节，第 5 章只列 Excel 文件名和四类用例数量，不重复用例表格。Excel 按既有工作簿模板保留四个分类工作表、五列结构和样式；先查找本任务或既有交付中的模板，找到后通过 `export_test_cases.py --template` 使用，替换旧用例并保留模板版式。找不到时按 references/test-point-contract.md 的表名、顺序、列头和内置样式生成。范围 Excel 只收录已复核的入选场景，不要求全量覆盖校验。默认目标为从仓库/修订可用起 10 分钟内完成，不因范围外义务尚未复核而标记草稿。报告及 Excel 由结构化材料生成，先校验章节、用例数量、模板字段和草稿状态，通过后再作为正式交付。若所选任务确实预计超过 10 分钟，可在超时后提供一次明确标记的阶段性草稿，但必须继续完成最终范围报告和 Excel；不得把草稿当作最终结果。只有源码、修订、权限、环境或关键业务预期等真实障碍使所选范围无法完成时，最终才交付标明缺口的报告和已完成范围内的用例。不得声称完成全量覆盖或正式全量校验。
5. 默认范围交付只维护一份结构化报告数据和一份四类用例数据。先用 `export_test_cases.py --scope-only` 生成模板 Excel，再用 `generate_report.py` 从结构化报告数据与用例数据生成带草稿标记的候选报告；生成器在候选写盘前校验固定章节、Mermaid 结构、项目/SHA 对应、配置代码块、既有功能影响说明、用例数量及分析边界，预校验失败时不写候选。按需用 `append_run_dirs.py` 登记分析目录，最后用 `validate_report.py --scope-only --finalize` 再次校验正文、范围边界、Excel 数量和草稿状态；全部通过后才定稿。校验前修改结构化来源并只重生成候选，不手工重写整份报告；候选输出已存在时仅允许以 `--replace-draft` 原位替换仍带完整草稿标记的文件。用户明确要求正式全量阶段时，执行 `validate_analysis.py`、`export_test_cases.py`、`append_run_dirs.py` 和 `validate_report.py` 的全量校验流程，传入当前 analysis/review/cases 及项目修订 expect 参数。检查导出内容与排版，如实说明未执行的构建、测试和联调。

默认范围报告优先检查改动主流程、资金/退款路径以及有证据的高风险边界；10 分钟是完成这份范围交付的目标，不是到时自动停止或交草稿的条件。范围内已复核的事实、配置前提、影响和可执行用例必须齐全；全量分析中未选义务只作为范围外数量/类别说明。普通访问器、没有关键结果数据流的辅助调用、预算边界及远距离解析缺口不单独形成复核项。静态证据足以回答的问题不运行本地模拟或受控探针；只有关键结论可能因此改变时才补充，并标明环境边界。不得为通过校验编造测试、证据或处置。遇到无法自行解决的源码、修订、权限、环境或关键业务预期障碍，交付列明已完成和缺口的未完成报告。

已核实事实、实际影响、范围外内容和验证边界必须写入本次报告，不能只留在内部记录。每次分析只维护一份滚动清单，测试点和用例在登记时查重并关联，禁止末尾整批归并。不能用“无”代替未查证内容；报告无法写入时说明错误和尝试位置。除真实阻塞外，不以中间草稿结束任务；超过 10 分钟的任务仍继续至最终范围报告和用例完成。进度答复不代替报告交付。

## 归属与输出

测试点唯一归属顺序为 **需求验收 > 既有核心流程回归 > 关联回归 > 业务规则与边界验证**，与风险等级、执行顺序分开。需求验收覆盖“本次功能改了什么，对应正常逻辑如何验证”；两类回归保护受本次影响的既有主流程和关联功能；异常、临界值及特殊组合归入业务规则与边界验证。详见测试点契约。各类可为空，但不能仅因缺少正式需求文档而将已核实的正常功能场景全部移入边界类；回归不铺开无关场景。

Excel 按以上四类分工作表，保留五列：用例编号、用例名称、前置条件、步骤描述、预期结果。固定条件和数据组自动补入前置条件，结构断言及观察证据补入预期结果。只接受当前四类输入和当前版本目录；其他历史格式直接拒绝。

Markdown 保留 [模板](assets/diff-list-template.md) 全部标题。范围报告和正式全量报告的第 5 章都只列独立 Excel 文件名、四类数量与总数；测试步骤和预期只写在 Excel，避免重复维护。范围报告只校验所选场景，明确未做全量覆盖校验；不得将范围外义务写成已验证。Mermaid 使用兼容 8.8.3 的 flowchart TD 或 sequenceDiagram；正文不展示本机源码路径、源码行号、内部编号或密钥。分析目录清单由脚本追加。

## 必须复核的边界

- 提交说明、语法候选、名称匹配和框架约定本身不证明需求正确性或运行时行为。经完整源码复核的功能变更可用于正常流程验收归类，不能据此声称正式需求已确认或实现必然正确。source_resolved/source_fact 仍需与完整上下文核对；没有候选、关系或覆盖义务不能直接判定无影响。
- 字段/常量变化的必要覆盖项不可省略；继承重载仅在参数类型支持时绑定，switch 保留分支来源与穿透边界。外部消费者、复杂别名和未解析类型仍需补查，能力及各层限额见 README。
- 测试点条件必须满足可解析的源码数量、分支、状态和来源约束，预期须保留明确来源/错误结果；角色别名用 source_bindings 显式对应。不得以复制义务、包装元数据或等价声明绕过；未自动解析的业务语义继续复核。
- 受影响变更 Java 索引失败、变更方法超过限额或关键变更证据缺失时阻断完整交付；动态绑定仅在可能影响关键业务结果时复核。限额外远距离预算/解析缺口不逐项复核，不把未扩展范围描述为已核实。补查使用同一项目的固定快照并保留证据；源码/修订错误不能用处置说明绕过。
- 字段、配置或契约变化需检查受影响的旧接口、历史数据和消费者；配置新增/沿用依据基线与最终相同作用域的支持情况，不依据环境记录是否存在。
- 项目名称和缩写只取自用户输入或已核实代码/文档，不自行创造或引入来源之外的缩写；首次出现说明已核实含义，不明确时使用直白中文。
- 校验结果只表示当前静态引用和结构声明通过；验证说明须区分源码复核、构建/测试和真实联调，不声称已执行未运行的测试。
